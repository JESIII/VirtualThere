3. What was checked by inspection, not by test

* `Capture.OpenAsync` still has exactly one caller in src/: `Vht.Core/Server/UsbIpSession.cs:417`
  (a client's OP_REQ_IMPORT). `VhtServerState.RefreshExportsAsync` and `ApplyHotplugChange` call

* The rebinder is still constructed only when `capture.rebind.enabled` is set
  (`Vht.Server/Hosting/ServerRuntime.cs`), so "never rebind without explicit intent" is unchanged:
  no new per-device opt-in was added, and the P2 gate in `WinUsbCaptureProvider.OpenAsync` is
  untouched.

--------------------------------------------------------------------------------
4. NOT RUN, and why
--------------------------------------------------------------------------------

* "Attach a device through a client, then detach: the local machine gets it back and it functions,
  without a reboot and without a manual pnputil. Paste the transcript."
  NOT RUN — moving a device needs an elevated process (`UpdateDriverForPlugAndPlayDevices` requires
  administrator rights; `elevated=False` above) and this shell cannot answer a UAC prompt. It also
  needs a USB/IP client session and a device that may safely be moved off its driver, and no device
  on this machine may be diverted from its function driver unattended.
  What stands in its place: the round trip is executed end to end against the fake machine above
  (record -> stage -> select -> re-select prior -> uninstall staged), and the unelevated refusal for
  the real machine is the next item.
* "Stop the server with a device attached: no device is left on winusb.sys."
  NOT RUN for the same reason (no device can be moved here). The code path is exercised:
  `ServerRuntime` cancels connections first and then calls `WinUsbCaptureProvider.DisposeAsync()`,
  which hands back every outstanding record, and `Provider_HandsBackEveryOutstandingRecord_OnShutdown`
  asserts the sweep runs.
* Real-machine rebind + handback of a live device (the `Restore` half on real hardware).
  NOT RUN — same elevation reason. Verified instead: the read half on this machine (section 1), and
  the failure mode that an unelevated handback produces: it returns the record unchanged, reports
  win32 5 and names the manual undo path, so a device is never reported as handed back when it is
  not.
